## infra：[f385cf8](https://github.com/titangene/goos-java/commit/f385cf806943b3ae2a308f225ef0f88f430c83a7) E2E 測試在 Xvfb 下執行

- commit message：

  ```text
  build(docker): run the end-to-end tests under Xvfb

  Passing check:
  docker compose run --rm --build toolbox bash -c 'echo "var f = new javax.swing.JFrame(); f.setVisible(true); print(\"frame showing: \" + f.isShowing()); java.lang.System.exit(0)" > /tmp/swing.js && xvfb-run -a jjs /tmp/swing.js; exit $?'
  ```
- 對應 `main` 分支：[4d4fb27](https://github.com/titangene/goos-java/commit/4d4fb272ee3b3c38f23887aceaff6b7743ae86c9)（部分）

### 這一步做什麼

- `toolbox.Dockerfile` 安裝 `xvfb`、`libxrender1`、`libxtst6`、`libxi6`
- `scripts/test.sh` 改用 `xvfb-run -a java ...`

### 設計理由

- 下一個紅燈要用 WindowLicker 找 Swing 視窗，沒有 display 時測試在斷言之前就失敗，不是合格的紅燈：
  - 在沒有 display 的 `eclipse-temurin:8-jdk-jammy` 容器內執行測試，`new GesturePerformer()` 拋出 `com.objogate.exception.Defect: could not create AWT robot`，原因是 `java.awt.AWTException: headless environment`
- 四個套件缺一不可（在乾淨容器內逐一安裝實測）：
  - 沒有 xvfb 也沒有 `DISPLAY`：`HeadlessException: No X11 DISPLAY variable was set`
  - 只裝 xvfb：`UnsatisfiedLinkError ... libXrender.so.1: cannot open shared object file`
  - 再裝 `libxrender1`：缺 `libXtst.so.6`
  - 再裝 `libxtst6`：缺 `libXi.so.6`
  - 再裝 `libxi6`：`frame showing: true`
- `curl` 還沒加：等 Openfire 出現、需要等它啟動時才加

### 驗證

指令：

```
docker compose run --rm --build toolbox bash -c '
  echo "var f = new javax.swing.JFrame(); f.setVisible(true); print(\"frame showing: \" + f.isShowing()); java.lang.System.exit(0)" > /tmp/swing.js &&
  xvfb-run -a jjs /tmp/swing.js
  exit $?
'
```

指令結尾的 `exit $?` 是必要的：少了它，`bash -c` 會把 `xvfb-run` exec 成 container 的 PID 1，指令會卡住（已實測，`ps aux` 看到 PID 1 是 `xvfb-run`，Xvfb 已啟動但 `jjs` 沒有被執行）

## infra：[6dedf7c](https://github.com/titangene/goos-java/commit/6dedf7ca96e8a8f91cfb8377900e441ef3f291f6) 用 Docker 跑 Openfire，toolbox 共用它的網路

- commit message：

  ```text
  build(docker): run Openfire and share its network with the toolbox

  Let Docker assign the host ports so they cannot clash.

  Passing check:
  docker compose up -d openfire && docker compose run --rm --build toolbox bash -c 'for i in $(seq 1 60); do curl -sf -o /dev/null http://localhost:9090 && echo "openfire is up" && exit 0; sleep 1; done; echo "openfire is not reachable"; exit 1'
  ```
- 對應 `main` 分支：[4d4fb27](https://github.com/titangene/goos-java/commit/4d4fb272ee3b3c38f23887aceaff6b7743ae86c9)（部分）

### 這一步做什麼

- `docker-compose.yml` 新增 `openfire` service
  - image `ghcr.io/igniterealtime/openfire:latest`
  - hostname `localhost`
  - port 9090 與 5222，host port 由 Docker 分配
  - volume `openfire-data`
- `toolbox` 改用 `network_mode: "service:openfire"`
- `toolbox.Dockerfile` 加上 `curl`
- `scripts/test.sh` 在跑測試前等 `localhost:9090` 有回應，最多 30 秒

### 設計理由

- 紅燈的 `FakeAuctionServer.startSellingItem()` 要真的連 XMPP
  - 已實測沒有 Openfire 時，測試失敗在 `connect()`，訊息是 `Connection refused`，那是環境錯誤，不是 Sniper 的行為缺失
- `network_mode: service:openfire` 讓 container 內的 `localhost` 就是 Openfire，測試與 production code 可以寫死 `"localhost"`
- host port 由 Docker 分配，避免多個 Compose 專案搶同一個 port；toolbox 共用 Openfire 的網路，不受影響

### 驗證

```

docker compose run --rm --build toolbox bash -c '
  for i in $(seq 1 60); do
    curl -sf -o /dev/null http://localhost:9090 && echo "openfire is up" && exit 0
    sleep 1
  done
  echo "openfire is not reachable"
  exit 1
'
```

### 設計理由

- 建立三個帳號 `sniper`、`auction-item-54321`、`auction-item-65432`：
  - 第一個 E2E 測項只用到 `sniper` 與 `auction-item-54321`

  - `auction-item-65432` 目前沒有測項用到，是之後的測項會用到，所以一起建立

- 等待條件改成 port 5222，因為測試與 app 連的是它，而且 Openfire 跑完 wizard 才會開這個 port；所以 healthcheck 要在這個 commit 才能加入

  - admin console 的登入表單有 hidden 欄位 `csrf`（已讀取 `login.jsp` 的 HTML 確認過了），所以先 GET 一次取得 token 與 cookie，再 POST 登入
