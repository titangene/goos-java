# ch11：第一個 E2E 測項轉綠，再重構成書中的結構

紅燈要三步才能轉綠：先顯示 `Joining` 視窗、再連線並送出空訊息、最後收到訊息顯示 `Lost`。前兩步是 `green-step`（測項仍是紅的，失敗點往後推進一格），第三步才是 `green`；全部先寫死在 `Main.main()`，再用重構逐步長出書中的結構（`MainWindow`、`AuctionSniperDriver`、`SingleMessageListener`），每一步都維持綠燈

  ```text
  feat(e2e): green-step 1/3 - show the Joining window from Main [11.2.2 p97]

  named "sniper status" and the text Joining, and does nothing else.
  ```

- `Main.main()` 用 `SwingUtilities.invokeAndWait(...)` 建立名為 `Auction Sniper Main` 的 `JFrame`，裡面放名為 `sniper status`、文字 `Joining` 的 `JLabel`

- 紅燈目前的第一個失敗點是找不到 `Auction Sniper Main` 視窗，這一步只處理這個失敗

- 因為還沒有 XMPP 程式碼，測項在這個 commit 之後仍然是紅的，失敗點只往後移一格

  ```text
  feat(e2e): green-step 2/3 - join the auction chat from Main [11.2.4 p100]

  ```

### 這一步做什麼

- 視窗建立之後，用 `new XMPPConnection(args[0])` 連線，以帳號 `args[1]`、密碼 `args[2]`、resource `Auction` 登入

- resource `Auction` 不是測試傳入的值，所以這裡寫成字面值
- JID 的網域部分仍然用 `connection.getServiceName()`，沒有寫死，因為網域由 Openfire 回報
- 送 `new Message()`（空 body）就夠了：目前的斷言只檢查 auction「收到訊息」
- `MessageListener` 傳 `null`：還沒有斷言需要處理 sniper 收到的訊息，實測 `createChat(..., null)` 可以正常執行
- 這個 commit 之後，只剩 `Lost` 檢查會失敗
